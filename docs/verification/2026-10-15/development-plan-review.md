# 개발 계획과 짧은 개발 요청의 실행 가능성 검토

날짜: **2026-10-15 (Asia/Seoul)**

대상 버전: `e14d801`에서 시작한 미커밋 문서 보강. 검토 대상은 [개발 지침](../../../AGENTS.md), [학습 로드맵](../../learning-roadmap.md), [챕터 작성 지침](../../chapter-authoring.md), [물리 검증 계획](../../physics-validation-plan.md), README, 실제 구현·시험·검증 스크립트·보고서의 대응 관계다.

목적은 사용자가 앞으로 “개발 진행해”만 요청해도 작업 선택·구현·검증·기록을 이어갈 수 있게 하는 것이다. 이번 검토는 **개발 계획 검토**이며 각 챕터 내용의 물리적 정합성을 새로 통과시킨 기록이 아니다.

## 실제 저장소 대조

확인 환경: Windows PowerShell, Node **v22.18.0**, Python **3.13.3**. 시작 시 `main`은 `origin/main`과 같고 사용자 미커밋 변경은 없었다.

실행 명령:

```powershell
node --test tests/*.test.cjs
```

결과: **24개 중 23개 통과, 1개 실패**. 실패한 시험 이름은 `published report pages and simulation assets have resolvable local links`이다. 첫 오류는 다음 파일을 읽을 때의 `ENOENT`다.

```text
docs/verification/2026-10-14/B00-physics.html
```

원인 확인:

- [physics 시험](../../../tests/physics-scientific.test.cjs)은 B00/B02/B03/B04의 `*-physics.html`을 존재하는 보고서로 나열한다.
- [보고서 생성기](../../../scripts/render-validation-reports.cjs)는 같은 ID의 `*-physics.md`를 기본 처리 대상으로 나열한다. 네 ID의 Markdown/HTML은 현재 저장소에 없다.
- [수정 후 검산 원문](../2026-10-14/fix-validation.md)도 없는 네 Markdown에 연결한다. 현재 생성 HTML과 원문에 차이가 있어 재생성만으로 일관성이 회복되지 않는다.
- 생성기의 기본 실행은 기존 HTML을 일부 쓴 뒤 누락된 원문에서 실패할 수 있다. 이번 문서 검토에서는 과거 보고서의 부분 덮어쓰기를 피하려고 생성기를 실행하지 않았으며 코드·입력 목록과 파일 존재 여부로 확인했다. 실제 생성 성공 확인은 W00의 인수 기준이다.

따라서 과거 “24개 통과” 기록은 당시 기록으로 보존하고, 현재 전체 시험 통과라고 보고하지 않는다. 누락된 보고서를 실제 물리 검증을 마친 것처럼 만들어 시험만 통과시키지 않는다.

## 문서 변경의 확인과 한계

- W00–W12의 의존성·인수 기준과 이후 핵심 챕터 순서를 원래의 챕터 목록에 대조했다. 주제 후보를 삭제하거나 미구현 챕터를 완료로 바꾸지 않았다.
- AGENTS → 실행 절차 → 로드맵 → 작성/물리 검증 → 실제 결과 기록의 연결을 확인했다. 다음 작업·작업 상태는 로드맵, 물리 판정은 물리 검증 계획에서 관리한다.
- 변경한 Markdown 7개에서 로컬 파일 링크 81개, 작업 13개의 고유 ID·카드 순서·의존성을 확인했다. 기존 핵심 챕터 51개와 확장 후보 22개의 보존, 기존 물리 판정 유지, 문서 외 파일 변경 없음, `git diff --check` 통과를 확인했다. 코드·HTML·수치 계산은 변경하지 않았으므로 이번 작업의 별도 화면/물리 검증은 수행하지 않았다.
- “개발 진행해”의 운영 기준을 문서에 마련했다. 실제 개발 요청을 수행한 결과와 장기 운영의 성공까지 검증한 것으로 보지 않는다. 새 챕터의 수치 범위·문헌·오차는 각 착수 때 구체화해야 한다.

절차를 다음 상황에 대조했다. 이는 문서상의 흐름 검토이며 실제 챕터 개발을 실행한 시험은 아니다.

| 상황 | 지침에 따른 다음 행동 |
|---|---|
| 지금 상세 지시 없이 개발 요청 | W00 복구를 구현·검증하고 결과와 다음 항목을 기록 |
| 계산은 구현했으나 모바일 확인이 남음 | 같은 작업을 재개하여 실제 화면을 확인, 완료 전 다음 챕터로 이동하지 않음 |
| 브라우저 사용이 외부 요인으로 차단됨 | 가능한 내용·수치 검토 후 미수행·재개 조건을 기록, 차단이 지속되면 독립 복구/문서 작업 선택 |
| 첫 묶음의 작업을 모두 완료 | 후속 순서의 첫 준비된 주제를 새 고유 작업 ID로 승격, 다음 카드들을 구체화하고 구현 |

다음 실행은 로드맵의 **W00**이다. 현재의 시험/보고서 기반을 복구한 뒤 C01의 통합 재검토로 이어진다.
