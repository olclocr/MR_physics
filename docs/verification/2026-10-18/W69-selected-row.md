# W69 · 고정 표 제목 아래의 선택 행 표시

2026-10-18. X05 농도, X01 단일 spin, X02 유입의 **표 표시 복구 완료**. 과학 모형을 새로 통과시킨 기록과 구별한다.

## 재현과 수정

세 페이지의 “표에서 선택값 보기”는 선택 행에 scrollIntoView의 nearest를 사용했다. 표를 끝으로 내린 뒤 첫/중간 행을 찾으면 행이 스크롤 영역 안에는 들어오지만 sticky 제목 셀 뒤에 가려졌다. 기존 영역 경계만 검사하는 검증은 이 문제를 발견하지 못했다.

각 페이지·1920×1080/390×844·첫/중간/끝 선택값·표의 위/아래 출발점으로 36경로를 검사했다. [수정 전 절차](W69-browser-before.js)와 [결과](W69-browser-before.json)에서 12건이 실제 제목 아래 기준을 만족하지 못했다. 예를 들어 X01 모바일의 중간 시각 행 상단519.84px는 제목 하단557.88px보다 위에 있었다.

선택 행에 위55px/아래10px scroll margin을 더했다. 공유 CSS·계산 코드·단위·설명·도식·정답은 바꾸지 않았다. [수정 후 절차](W69-browser-after.js)와 [결과](W69-browser-after.json)는 같은36경로에서 행 전체가 제목 셀 아래와 영역 끝 안에 드는지 1px 반올림 허용으로 확인했다. 가림0, JS 오류0, 페이지 가로 넘침0이며 키보드 Home/End·Enter 버튼 실행과 모바일 표 가로 스크롤도 통과했다.

[수정 전 모바일](W69-before-flow_gradient_phase-390.png)과 [수정 후 모바일](W69-after-flow_gradient_phase-390.png)을 직접 열어 선택 시각2ms의 행과 전체 열 표시 위치를 비교했다. 데스크톱/나머지 두 페이지도 같은 수치 기준과 스크린샷을 남겼다.

## 변경 영향과 판정

[작업 전 입력 목록](checkpoint-W69-inputs.json)은 현재 사용하는62개 물리 manifest의447개 중복 제거 입력을 고정했다. 초기 조사에서 오래된 중간 manifest도 포함하면 후속 작업에서 이미 갱신된 과거 페이지를 잘못 차이로 잡으므로, W67이 정리한 현재 범위에 W64를 더했다. 과거 중간 기록은 그대로 보존했다.

[감사 절차](W69-final-audit.cjs), [결과](W69-audit.json)는 세 HTML에서 추가한 CSS 문자열만 제거하면 작업 전 raw SHA-256과 정확히 일치하는지 확인한다. 나머지444입력은 바이트 불변이다. 36경로의 전체 원표 텍스트/지표 텍스트 SHA도 수정 전후 일치했다. 따라서 계산·물리 판정은 [X05](../2026-10-17/X05-physics.md), [X01](../2026-10-17/X01-physics.md), [X02](../2026-10-17/X02-physics.md)의 기존 범위를 유지한다. HTML 표시 변경 후 실제 표 접근성만 이번 범위에서 재검증했다.
