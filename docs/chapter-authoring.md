# 챕터 작성과 유지 지침

대상: 영상의학과 의사·전공의. 방향: 물리 원리로 영상의 변화와 판독의 함정을 설명할 수 있게 한다.

## 착수 전에 정할 사항

작업 선택과 완료·재개는 [개발 진행 절차](development-workflow.md), 실제 순서는 [로드맵의 실행 대기열](learning-roadmap.md)을 따른다. 새 챕터를 시작할 때 아래 설계 메모와 해당 작업 카드로 결과물을 구체화하고 같은 요청에서 구현한다.

- 목표·관찰 과제마다 어떤 화면 변화와 확인 문제로 이해를 확인할지 연결한다. 학습자가 한 조건씩 바꾸며 원인을 비교할 수 있는 기본 화면을 먼저 정한다.
- 조작별 이름·단위·기본값·최소/최대·step과 허용 조합을 정한다. 범위 밖/비어 있는 숫자 입력의 처리, 초기화 후 상태, 시각화 간 동기화도 정한다.
- 이번 작업에서 구현할 현상과 후속으로 남길 현상을 구분한다. 한 페이지에 새 기전이 늘어나면 기존 ID의 추적을 유지하며 작은 작업으로 나눈다.
- 계산 모형·값·핵심 주장의 근거를 실제로 확인한다. 원전·교과서·논문·공식 기술 문서를 우선하며 주제 소개 페이지 하나만으로 모든 핵심 주장의 근거를 대신하지 않는다. 예시값과 근거에서 가져온 값을 구분한다.

## 페이지를 나누는 기준

- 한 페이지의 중심 질문은 하나, 학습 목표는 최대 세 개로 잡는다. 기본 학습은 약 8–12분을 목표로 한다.
- 같은 모형에서 한두 조건만 바꾸며 비교하는 T1W·T2W·PDW는 한 페이지로 묶는다.
- 새 신호 기전, 새 획득 방식, 독립적인 해석 절차가 추가되면 분리한다. 예: T2W와 T2 mapping, IP/OP와 Dixon, DWI와 ADC 심화, AI 원리와 벤더 비교.
- 같은 개념을 중복 구현하지 않는다. 예: STIR의 TI 원리는 IR 챕터에서 배우고, 지방억제 선택 챕터는 그 내용을 연결한다.
- 새 페이지에 들어가지 않는 질문은 삭제하지 않고 로드맵에 후속 챕터 또는 보강 과제로 남긴다.

## 모든 챕터의 기본 형식

1. **중심 질문과 목표:** 임상 영상을 보며 생기는 질문으로 시작한다. 목표를 세 문장 이내로 제시한다.
2. **선행 지식:** 필요한 수학·물리 개념을 2–4문장으로 설명하고 기존 챕터에 연결한다. 기호와 단위를 정의한다.
3. **기초 개념:** 먼저 일상적인 설명과 간단한 도식, 다음에 선택해서 펼치는 수식을 제공한다.
4. **예측과 관찰:** 결과를 먼저 예상한 뒤 한 조건씩 바꾸는 2–3개 과제를 제공한다. 초기화와 대표 예시를 제공한다.
5. **연결된 시각화:** 같은 상태와 계산으로 도식·곡선·수치·영상을 갱신한다. 색 외에도 이름·선·수치로 구분한다.
6. **흔한 오개념:** 잘못된 생각 → 왜 틀렸는지 → 화면에서 확인하는 방법을 연결한다.
7. **학습 확인:** 단순 암기보다 조건이 달라진 상황에 적용하는 1–3개 질문과 설명형 피드백을 제공한다.
8. **추가 질문과 다음 학습:** 이번 모델에서 설명되지 않는 질문을 다음 챕터로 연결한다. 미구현 챕터에는 깨진 링크를 만들지 않는다.
9. **가정·한계·근거:** 모델의 정확한 범위, 합성 영상 여부, 값의 출처 또는 예시값 여부, 참고 문헌을 공개한다.

## 시뮬레이션과 과학 검증

- 검증 가능한 순수 계산 함수를 사용하고 UI가 따로 유사한 계산식을 복제하지 않도록 한다.
- 근사식과 더 정확한 식을 혼용하지 않는다. 설명용 근사식을 쓸 경우 표시값을 계산하는 식과 차이를 설명한다.
- 실제 값 표가 아닌 예시 조직값에는 그 사실을 명시한다. 신호를 임의의 진단 가능성이나 질병명으로 해석하지 않는다.
- 자동 windowing·정규화로 조건 변화가 가려지지 않게 한다. 표시 창을 고정하거나 변경 여부를 명시한다.
- 독립적 해석식·적분·기준값 또는 불변량으로 수치를 확인한다. 구현을 그대로 복사한 시험은 검산으로 간주하지 않는다.
- 대표 상태, 조작 경계, 초기화, 키보드 조작, 반응형 화면을 확인한다. 현재 프로젝트의 기존 시험도 실행한다.
- 실제 브라우저에서 데스크톱(가능하면 1920px)과 모바일(390px 전후)을 확인한다. 실행 오류·겹침·잘림·빈 canvas를 확인하고 기록한다.
- 키보드로 주요 조작과 초기화를 수행할 수 있게 하고 입력·버튼의 이름과 단위를 연결한다. canvas의 핵심 정보는 수치·범례·텍스트로도 제공한다. 애니메이션에는 정지/관찰 수단을 두고 시간 진행과 물리적 시간축을 구별한다.
- 큰 matrix·많은 표본 등 허용 범위의 무거운 상태도 실제 브라우저에서 조작해 본다. 모바일에서 멈춤이나 입력 지연이 학습을 방해하면 범위·계산 주기·구현을 조정하고 그 한계를 기록한다.

## 구현 이후 내용의 물리적 정합성 검증

모든 챕터에 [물리 검증 계획](physics-validation-plan.md)의 해당 ID 항목을 적용한다. 구현 작업에는 **계획 구체화 → 내용·근거 대조 → 독립 검산 → 화면과 물리 모형 대조 → 수정·재검증 → 판정 기록**을 포함한다. 설명 중심 챕터도 핵심 주장·도식·반례·퀴즈 정답을 검토한다.

- 단위·좌표·부호·시간 기준, 근사와 실제 현상의 차이, 조직값과 표시 정규화의 의미를 대조한다.
- 예상 동작을 구현 함수로만 확인하지 않고 독립 계산 또는 근거를 사용한다. 허용 오차는 결과를 보고 임의로 정하지 않고 검증 설계에서 명시한다.
- 물리적으로 확인한 결과와 화면의 설명·표·곡선·영상·정답을 연결해 확인한다. 내용 검토와 렌더링 점검을 구분한다.
- 문제 발견 시 해당 상태를 **수정 필요**로 기록하고 해결·재검증도 남은 개발에 포함한다. 기존 검토 기록의 발견 사항을 삭제하지 않는다.
- 검증은 특정 버전과 범위에 대한 판정이다. 모형·내용·표시의 관련 변경 후 영향을 받는 항목을 다시 확인한다.
- 구현이 있어도 내용 검증이 남으면 **페이지 구현 / 물리 검증 대기**로 표시한다. 계획을 기록했다는 이유로 통과했다고 표시하지 않는다.

검증 결과는 `docs/verification/<날짜>/<chapter-id>-physics.md`에 저장하고 물리 검증 계획과 로드맵에서 연결한다. 외부 전문가 검토 여부는 별도로 기록한다.

## 작업마다 갱신할 기록

`learning-roadmap.md`를 학습 구성과 진행 상태의 기준 문서로 사용한다.

1. 해당 챕터 ID의 구현 상태·파일·남은 일을 수정한다.
2. 새 페이지나 학습 순서 변경을 `index.html`과 `README.md`에 반영한다.
3. 변경 기록에 날짜, 챕터 ID, 구현 내용, 수행한 검증, 남은 한계를 기록한다.
4. 상태는 **계획 / 부분 구현 / 페이지 구현**으로 기록한다. 시험·조작·브라우저 확인은 실제 수행 범위를 기록한다. 물리 검증은 계획 문서의 **미착수 / 재검토 대기 / 검토 중 / 수정 필요 / 대상 버전 통과** 상태를 별도로 기록한다.
5. 여기의 검증 완료는 교육용 구현 검증을 의미한다. 임상 프로토콜 승인 또는 외부 전문가의 내용 검토와 동일하지 않다.
